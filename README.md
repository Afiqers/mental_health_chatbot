# Mindbot — NLP-Based Sentiment Analysis Mental Health Chatbot

A bilingual (English / Malay) mental-health support chatbot built around an
NLP sentiment-analysis pipeline. It classifies the emotional state behind each
message, replies with an empathetic, LLM-rephrased response, and tracks the
user's mood over time on a personal dashboard.

> ⚠️ Mindbot is an AI companion for educational/FYP purposes — **not** a
> substitute for professional care. Crisis resources (Talian Kasih 15999,
> Befrienders KL 03-7627 2929) are surfaced automatically when self-harm
> language is detected.

---

## Features

- **Bilingual sentiment / emotion classification** — a fine-tuned DistilmBERT
  model, trained on a balanced English + Malay dataset, classifies messages into
  `ANXIETY`, `DEPRESSION`, `SUICIDAL`, `NORMAL` and returns a full probability
  distribution. ~80% accuracy on **both** languages (see the evaluation below).
- **Continuous wellbeing score** — the distribution is collapsed into a single
  score in `[-1, +1]` (see [`backend/sentiment.py`](backend/sentiment.py)), which
  powers the mood trend analytics.
- **Hybrid safety design** — an ML-primary classifier with a transparent rule
  layer: a deterministic **crisis safety net** for explicit self-harm language,
  and a **lexicon backstop** that rescues the model's rare false-negatives
  (clear distress mislabelled as NORMAL — the dangerous direction here).
- **Context-aware conversation** — replies are generated by an LLM (Google
  Gemini by default, with automatic fallback to local Ollama) grounded in the
  *whole* conversation, in the "Solace" persona, matching the user's language and
  emotional tier. The classifier also carries emotional state across short
  follow-ups (e.g. "yeah", "it's my exams") so the bot doesn't lose the thread,
  and resets when the user signals they feel better. Falls back to a curated
  response bank if no LLM is reachable.
- **Accounts & persistence** — JWT auth (bcrypt-hashed passwords), multiple
  conversations per user, full chat history stored in SQLite.
- **Mood dashboard** — sentiment-over-time line chart, emotion-distribution
  doughnut, and headline stats (average mood, trend, high-risk flags).
- **Model evaluation** — [`backend/evaluate.py`](backend/evaluate.py) produces a
  confusion matrix, per-class precision/recall/F1, and accuracy/macro-F1.

## Architecture

```
Frontend (vanilla JS SPA, Chart.js)
        │  REST + JWT
        ▼
Flask backend (blueprints)
  ├── auth.py             register / login / me
  ├── routes_chat.py      /chat + conversation CRUD
  ├── routes_analytics.py /analytics/{summary,mood,emotions}
  │
  ├── model.py            BERT classifier + crisis net + context carry-forward
  ├── sentiment.py        distribution → wellbeing score
  ├── response_generator.py   routing: crisis / contextual reply / fallback
  ├── llm_rephraser.py    LLM contextual generation (Gemini/Ollama/Claude) + language detection
  └── database.py         User / Conversation / Message (SQLite)
```

Request flow for `/chat`: `classify_text` (with prior emotion for context) →
`score_from_distribution` → `generate_response` → `generate_contextual_reply`
(or template fallback) → persist user + bot messages → JSON.

## Setup

### 1. Backend

```bash
cd backend
pip install -r requirements.txt
```

The fine-tuned model lives in `backend/local_model/` (git-ignored). If absent,
the app falls back to a public model from Hugging Face.

### 2. Response generation backend

Replies are generated by an LLM (`LLM_PROVIDER`, default **`gemini`**). The chain
degrades gracefully: **Gemini → Ollama → curated response bank**, so the app
always produces a reply even with no LLM available.

**Option A — Google Gemini (default, free tier).** Uses **gemini-2.5-flash-lite**.
Put your key in a `.env` file at the project root (gitignored — never committed):

```bash
# .env
GEMINI_API_KEY=your-key-here
LLM_PROVIDER=gemini
```

If Gemini is rate-limited (HTTP 429) or unreachable, the app automatically falls
back to local Ollama, then to the curated response bank.

**Option B — Ollama (local, free).** Set `LLM_PROVIDER=ollama`, then install
[Ollama](https://ollama.com) and `ollama pull llama3.2`.

**Option C — Claude API.** Set `LLM_PROVIDER=claude` and `ANTHROPIC_API_KEY`;
uses Claude Haiku 4.5 (cheapest model, small `max_tokens` cap to keep cost down).

### 3. Run

```bash
# Terminal 1 — backend (from backend/)
python app.py            # serves http://127.0.0.1:5000

# Terminal 2 — frontend (from project root)
python -m http.server 8080 --directory frontend
```

Open <http://127.0.0.1:8080>, create an account, and start chatting.

## Training & evaluating the classifier

Retrain the bilingual model (English + Malay) from the raw datasets:

```bash
python train_bilingual.py        # from project root; saves to backend/local_model/
```

This also writes `backend/eval_output/bilingual_report.txt` with **separate
English vs Malay** test metrics (evidence of bilingual capability).

Evaluate the current model and produce a confusion matrix:

```bash
cd backend
python evaluate.py               # held-out split; writes to backend/eval_output/
```

Artifacts: `confusion_matrix.png`, `classification_report.txt`, `metrics.json`.

**Held-out results (DistilmBERT, bilingual):** ~79% overall accuracy
(English 80%, Malay 78%), macro-F1 ≈ 0.79.

### Deeper analysis (report evidence)

All three reuse the *same* held-out test split (`backend/data_utils.py`) so
results are directly comparable and leakage-free:

```bash
cd backend
python baseline_comparison.py    # DistilmBERT vs TF-IDF + LogReg / LinearSVM
python safety_eval.py            # crisis-detection recall / precision
python error_analysis.py         # qualitative misclassification breakdown
```

- **Baseline comparison** — DistilmBERT (0.79 F1) clearly beats TF-IDF + LogReg
  (0.68) and TF-IDF + LinearSVM (0.70), justifying the deep-learning choice.
  → `baseline_comparison.{txt,png}`
- **Safety evaluation** — binary crisis detection: **~81% recall**, 0 false
  alarms on safe text, and the deterministic safety net catches 14/14 explicit
  self-harm phrases. → `safety_report.txt`
- **Error analysis** — the dominant confusion is DEPRESSION↔SUICIDAL (shared
  hopelessness vocabulary), motivating the crisis safety net. → `error_analysis.txt`

## Configuration

All settings are environment-overridable via the environment or a gitignored
`.env` file at the project root (see [`backend/config.py`](backend/config.py)):
`SECRET_KEY`, `JWT_SECRET_KEY`, `DATABASE_URL`,
`LLM_PROVIDER` (`gemini`|`ollama`|`claude`),
`GEMINI_API_KEY`, `GEMINI_MODEL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`,
`ANTHROPIC_MAX_TOKENS`, `OLLAMA_MODEL`, `OLLAMA_URL`, `OLLAMA_TIMEOUT`.
